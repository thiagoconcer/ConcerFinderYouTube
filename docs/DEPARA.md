# DE-PARA — Matriz de Rastreabilidade — ConcerFinder

> **Objetivo:** garantir que nenhuma tabela, function/endpoint ou página fique órfã. Use este documento como checklist de consistência entre `docs/ESTRUTURA.md` (banco/backend) e as páginas do frontend React.
> Nomes: `snake_case` para tabelas e RPCs Postgres; `kebab-case` para Edge Functions e rotas de página.

---

## Tabela 1 — Tabela (DB) → Functions/Endpoints → Páginas

| Tabela | Functions/Endpoints que a tocam | Páginas que a usam | Observação |
|---|---|---|---|
| `profiles` | `handle_new_user()` (trigger INSERT no signup), `register-lead` (garante/atualiza perfil), `search_videos` (lê `profile_id` via `auth.uid()`), `get_audience_insights()` (agrega por `commercial_role`), `is_concer_staff()` (lê `role`) | `sign-up` (cria via trigger), `login`, `search` (identidade do usuário), `admin-audience` (perfis + `commercial_role`) | RLS: dono (`id = auth.uid()`) ou staff. Nunca deletado pelo frontend (só `service_role`). Papéis internos atribuídos manualmente. |
| `leads` | `register-lead` (INSERT `nurture_status='pending'` + dispara webhook), `nurture-webhook-callback` (UPDATE `nurture_status`/`nurture_sent_at`) | `sign-up` (dispara o INSERT indireto via Edge Function), `admin-audience` (SELECT staff) | INSERT/UPDATE só `service_role`. SELECT só staff. Frontend nunca escreve direto — passa por `register-lead`. |
| `videos` | `scrape-youtube-channel` (upsert), `transcribe-videos` (UPDATE `transcription_status`), `index-segments` (UPDATE `indexed_at`/`transcription_status='indexed'`), `search_videos` (JOIN nos resultados) | `search` (título/thumb nas recomendações), `video-detail` (metadados + deep-link), `admin-content` (status por vídeo) | SELECT liberado a qualquer autenticado; escrita só `service_role`. Staff pode marcar revisão. |
| `video_segments` | `transcribe-videos` (INSERT segmentos), `index-segments` (UPDATE `embedding`), `search_videos` (busca vetorial por cosseno), `get_search_results` / `get_video_detail` (leitura via RPC) | Nenhuma página lê direto — acesso apenas via RPC `SECURITY DEFINER` | Índice vetorial `hnsw` sobre `embedding`. RLS bloqueia SELECT pelo frontend por regra de negócio (visitante não vê nada). As RPCs de leitura só devolvem trechos que o usuário já recuperou em buscas próprias. |
| `cta_clicks` | inserida pelo frontend com a RLS do próprio dono; lida por staff e pela view `analytics.fato_cliques_cta` | `search` e `search-history` (clique no CTA do plano de ação) | INSERT só do próprio (`profile_id = auth.uid()`), SELECT só staff, sem UPDATE nem DELETE para ninguém. `destino` e `local` são texto livre: banner lateral e barra fixa entram sem migration. |
| `searches` | `search_videos` (INSERT da busca + `detected_topics`), `generate-action-plan` (UPDATE `action_plan`, `context_answer`, `plan_has_context`), `context-question` (UPDATE `context_question`, `context_options`), `get_busca_detail()` (lê a busca inteira para a equipe), `get_contexto_insights()` (agrega pergunta e resposta), `get_audience_insights()` (agrega `detected_topics`), `get_search_results` (lê) | `search` (registra cada dor buscada), `search-history` (lista buscas do próprio usuário), `admin-audience` (temas mais buscados) | RLS: dono (`profile_id = auth.uid()`) ou staff. INSERT pelo dono/RPC. |
| `search_results` | `search_videos` (INSERT das recomendações rankeadas via RPC), `get_search_results` / `get_video_detail` (leitura) | `search` (exibe vídeo + minutagem + score), `search-history` (resultados de buscas anteriores), `video-detail` (trechos do vídeo) | SELECT: dono da busca associada ou staff. INSERT só `service_role`/RPC. Guarda `start_seconds` para o deep-link. |
| `video_views` | `get_audience_insights()` (agrega recomendado × assistido) | `video-detail` (INSERT ao abrir), `admin-audience` (rankings) | **[Extensão do doc]** SELECT: dono ou staff. INSERT: só o próprio usuário. UPDATE/DELETE: ninguém, métrica não se edita. |
| `limites_de_uso` | `limite_de_busca()` (lê o teto), `search_videos` (aplica) | nenhuma | **[Extensão do doc]** Teto de buscas por pessoa. Em tabela, e não no código, para afrouxar ou apertar sem republicar Edge Function. SELECT liberado a quem está logado (a pessoa pode saber quanto ainda pode buscar); escrita só `service_role`. |
| `ingestion_runs` | `scrape-youtube-channel` (INSERT `run_type='scrape'`), `transcribe-videos` (INSERT `run_type='transcribe'`), `index-segments` (INSERT `run_type='index'`), `get_content_dashboard()` (agrega) | `admin-content` (log de execuções de scraping/transcrição/indexação) | SELECT só staff; escrita só `service_role`. Monitoramento da esteira de ingestão agendada por pg_cron. |

## Tabela 2 — Function/Endpoint → Tabelas → Páginas (caminho inverso)

| Function/Endpoint | Tabelas que toca | Página(s) que chama | Observação |
|---|---|---|---|
| `register-lead` (Edge) | `profiles` (upsert), `leads` (INSERT + UPDATE nurture) | `sign-up` | Chamada no submit do cadastro. Dispara webhook de nutrição (Make → ActiveCampaign + WhatsApp / N8N existente). |
| `scrape-youtube-channel` (Edge) | `videos` (upsert `pending`), `ingestion_runs` (INSERT `scrape`) | `admin-content` (botão manual) + pg_cron diário | Fonte: YouTube Data API v3 com Apify de fallback. Primeiro passo da esteira de ingestão. |
| `transcribe-videos` (Edge) | `videos` (UPDATE status), `video_segments` (INSERT segmentos), `ingestion_runs` (INSERT `transcribe`) | Nenhuma (cron + gatilho pós-scrape) | STT (ex.: OpenAI Whisper). Quebra transcrição em janelas de tempo. |
| `index-segments` (Edge) | `video_segments` (UPDATE `embedding`), `videos` (UPDATE `indexed`), `ingestion_runs` (INSERT `index`) | Nenhuma (cron + pós-transcrição) | Embeddings `text-embedding-3-small` (1536 dims) via API OpenAI. |
| `search-pain` (Edge) | nenhuma diretamente; chama a RPC `search_videos` com o JWT do usuário | `search` | **[Extensão do doc]** Gera o embedding da dor no servidor, porque a chave de embeddings não pode ir ao frontend. Também detecta os `detected_topics`. |
| `context-question` (Edge) | `searches` (UPDATE `context_question`, `context_options`) | `search` (em paralelo com o plano, depois dos trechos) | Gera com Claude, a partir da dor E dos trechos, UMA pergunta cuja resposta mudaria o plano, com 2 a 4 respostas sugeridas. A pergunta NÃO segura o plano: aparece acima dele enquanto ele é escrito, e responder o reescreve. Segurou por um dia, em 21/08, e 4 de 5 pessoas saíram sem plano nenhum. Pode devolver `null` (dor já detalhada, busca sem trecho, falha). Idempotente por busca. **[Extensão do doc]** |
| `generate-action-plan` (Edge) | `searches` (UPDATE `action_plan`) | `search` (dentro do fluxo de busca) | LLM Claude Opus 5 (contexto de 1M tokens) para consolidar insights dos top segmentos; Claude Sonnet 5 como alternativa custo-eficiente em alto volume. Idempotente: se o plano já existe, devolve o gravado sem nova chamada ao LLM. Com `context_answer`, regera UMA vez com o contexto e marca `plan_has_context`. |
| `nurture-webhook-callback` (Edge) | `leads` (UPDATE `nurture_status`) | Nenhuma (webhook externo do Make/N8N) | Recebe status de entrega da régua de nutrição e fecha o ciclo do lead. |
| `search_videos(query_embedding, match_count)` (RPC, SECURITY DEFINER) | `video_segments` (busca vetorial), `videos` (JOIN), `searches` (INSERT), `search_results` (INSERT), `profiles` (`profile_id` via `auth.uid()`) | `search`, `search-history` | Núcleo do produto. Exige `auth.uid()` válido — visitante sem cadastro não recebe recomendação. |
| `handle_new_user()` (RPC/trigger) | `profiles` (INSERT) | `sign-up` (disparada pelo signup no Supabase Auth) | Trigger em `auth.users`. Papel padrão `user`. |
| `is_concer_staff()` (RPC helper) | `profiles` (lê `role`) | `admin-content`, `admin-audience` (guarda de acesso staff) | Helper de RLS usado nas policies dos painéis internos. Aceita `content_admin`, `audience_manager` e `admin`. |
| `is_concer_admin()` (RPC helper) | `profiles` (lê `role`) | `admin-audience` (seção de equipe) | **[Extensão do doc]** Só `admin`. Usado por `get_equipe`, `definir_papel` e pelo trigger anti-escalação. |
| `get_equipe()` (RPC, SECURITY DEFINER, admin-only) | `profiles`, `searches` | `admin-audience` | **[Extensão do doc]** Lista a equipe com papel e volume de buscas. |
| `definir_papel(p_profile_id, p_role)` (RPC, SECURITY DEFINER, admin-only) | `profiles` (UPDATE `role`) | `admin-audience` | **[Extensão do doc]** Única via de alteração de papel. Recusa papel inválido e impede o admin de se rebaixar. |
| `protege_papel_do_profile()` (trigger BEFORE UPDATE em `profiles`) | `profiles` | nenhuma | **[Extensão do doc]** Bloqueia mudança de `role` por quem não é admin. Corrige a escalação de privilégio descrita na ESTRUTURA. |
| `get_audience_insights()` (RPC, SECURITY DEFINER, staff-only) | `searches` (`detected_topics`), `profiles` (`commercial_role`), `leads`, `search_results`, `video_views`, `videos`, `video_segments` | `admin-audience` | Cruza dores buscadas × perfil comercial para segmentação de audiência (base do modelo de receita). |
| `get_cargo_insights()` (RPC, SECURITY DEFINER, staff-only) | `profiles` (`cargo`), `searches` (`detected_topics`) | `admin-audience` | **[Extensão do doc]** Corte por cargo (9 opções, iguais às do ActiveCampaign) em vez do perfil (3). Separada de `get_audience_insights` porque é pergunta nova e a outra não precisava mudar. |
| `limite_de_busca()` (RPC, SECURITY DEFINER) | `limites_de_uso`, `searches` | `search` (via `search-pain`) | **[Extensão do doc]** Quanto a pessoa ainda pode buscar na hora e no dia. Conta em cima de `searches`, que já é o registro autoritativo: não existe contador paralelo para dessincronizar. Staff é ilimitado. |
| `perfil_do_cargo(p_cargo)` (RPC helper, IMMUTABLE) | nenhuma | nenhuma | **[Extensão do doc]** Regra canônica cargo → perfil comercial. Serve também de CHECK das colunas `cargo`: cargo válido é o que ela sabe traduzir. |
| `deriva_perfil_do_cargo()` (trigger BEFORE INSERT/UPDATE OF `cargo` em `profiles` e `leads`) | `profiles`, `leads` | nenhuma | **[Extensão do doc]** Reescreve `commercial_role` a partir do `cargo`, venha a gravação de onde vier. Sem isso uma rota que esquecesse de derivar colocaria a pessoa na régua errada. |
| `get_engagement_insights()` (RPC, SECURITY DEFINER, staff-only) | `profiles`, `searches`, `search_results`, `video_views`, `videos`, `video_segments` | `admin-audience` | **[Extensão do doc]** Crescimento (série diária), funil de ativação, qualidade da busca, pauta de conteúdo por tema e acervo ocioso. Separada de `get_audience_insights` porque responde outras perguntas: aquela é "quem procura o quê", esta é "o produto está funcionando e o acervo dá conta". |
| `get_origem_insights()` (RPC, SECURITY DEFINER, staff-only) | `leads` (UTM + referrer), `searches` (ativação) | `admin-dashboard` | **[Extensão do doc]** De onde vêm os leads, com quantos de cada origem chegaram a buscar. Volume sem ativação é tráfego, não audiência. |
| `origem_do_lead(p_utm_source, p_referrer)` (RPC helper, IMMUTABLE) | nenhuma | nenhuma | **[Extensão do doc]** UTM quando existe, senão o domínio do referrer, senão `direto`. Nunca devolve vazio: a maior parte do tráfego vem do canal sem parâmetro, e um relatório só de UTM esconderia a fonte principal. |
| `get_leads(p_busca, p_perfil, p_limit, p_cargo, p_origem, p_regua, p_tema, p_faixa, p_atividade, p_desde, p_incluir_internos)` (RPC, SECURITY DEFINER, staff-only) | `profiles`, `leads`, `searches`, `video_views`, `cta_clicks` | `admin-leads` | **[Extensão do doc]** Lista de pessoas com comportamento já resumido, em um round-trip. Busca textual cobre nome, e-mail, WhatsApp e o texto das dores pesquisadas. Filtros combinam entre si: cargo, origem (via `origem_do_lead`), situação na régua (`sem_regua` é quem nunca entrou, diferente de quem falhou), tema buscado, faixa de score e atividade (buscou, cadastrou e não buscou, abriu trecho, clicou no convite). Conta interna fica de fora por padrão. |
| `get_leads_facetas()` (RPC, SECURITY DEFINER, staff-only) | `profiles`, `leads`, `searches` | `admin-leads` | **[Extensão do doc]** As opções de filtro que existem de fato, com contagem. Origem é aberta, então a tela não pode ter lista fixa. |
| `get_lead_detail(p_profile_id)` (RPC, SECURITY DEFINER, staff-only) | `profiles`, `leads`, `searches`, `search_results`, `video_views`, `videos` | `admin-lead-perfil` | **[Extensão do doc]** Ficha completa: buscas com temas e se geraram plano, e os trechos abertos de verdade. |
| `nurture-status` (Edge, staff-only) | nenhuma; lê o ActiveCampaign | `admin-leads`, `admin-lead-perfil` | **[Extensão do doc]** Em que etapa da régua cada pessoa está. Busca POR TAG (7 chamadas fixas) e não por contato (uma por lead), senão a página não abriria com a base grande. Falha vira `disponivel: false`, nunca 500: o dado de comportamento é nosso e continua útil. |
| `get_search_results(p_search_id)` (RPC, SECURITY DEFINER) | `searches`, `search_results`, `videos`, `video_segments` | `search-history` | **[Extensão do doc]** Reabre resultados persistidos. Só do dono da busca ou staff. |
| `get_video_detail(p_video_id)` (RPC, SECURITY DEFINER) | `videos`, `video_segments`, `search_results`, `searches` | `video-detail` | **[Extensão do doc]** Metadados + trechos que o próprio usuário já recuperou. |
| `get_content_dashboard()` (RPC, SECURITY DEFINER, staff-only) | `videos`, `video_segments`, `ingestion_runs` | `admin-content` | **[Extensão do doc]** Contadores da esteira de ingestão. |
| `run_ingestion_step(step)` (função interna, SECURITY DEFINER) | nenhuma; faz `net.http_post` para a Edge Function da etapa | nenhuma (só pg_cron) | **[Extensão do doc]** Lê o segredo do Vault e envia em `X-Cron-Secret`. EXECUTE revogado de anon/authenticated. |

### Checklist de órfãos (conferência rápida)

- **Todas as 8 tabelas** aparecem na Tabela 1: `profiles`, `leads`, `videos`, `video_segments`, `searches`, `search_results`, `ingestion_runs`, `video_views`. ✔
- **Todas as 7 Edge Functions + 8 RPCs/funções** aparecem na Tabela 2. ✔
- **Todas as 8 páginas** são referenciadas por ao menos uma function/tabela: `landing` (institucional, sem dados — CTA para `sign-up`), `sign-up`, `login`, `search`, `search-history`, `video-detail`, `admin-content`, `admin-audience`. ✔
- **`landing`** é a única página sem escrita/leitura de dados de negócio (apresentação + CTA); intencional, não é órfã de propósito.
- **`video_segments`** intencionalmente sem página direta — só via `search_videos` (regra de negócio de acesso restrito). ✔
